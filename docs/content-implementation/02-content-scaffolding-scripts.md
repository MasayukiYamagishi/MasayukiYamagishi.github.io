# コンテンツ作成用スクリプト

## 目的

PostsとProjectsの追加時に必要なディレクトリと初期ファイルを、再現可能なコマンドで生成する。既存ファイルは上書きせず、slugの誤りを作成前に検出する。

## 現状

Postsには既に次のコマンドがある。

```powershell
pnpm post:new -- --slug my-first-post
```

`scripts/create-post.mjs` は次を生成する。

```text
src/content/posts/<slug>/
├─ post.yaml
├─ ja.mdx
└─ en.mdx

assets/posts/<slug>/
└─ content/
   └─ .gitkeep
```

slug検証、既存ディレクトリの事前確認、日本時間の公開日初期値、上書き防止は実装済みである。Projects用の生成コマンドは未実装である。

## 設計判断

当面は、PostsとProjectsで別々の明示的なコマンドを維持する。

```powershell
pnpm post:new -- --slug <slug>
pnpm project:new -- --slug <slug>
```

両者は生成するファイルや次の作業が異なるため、現時点で `content:new --type ...` のような統合CLIを作る利点は小さい。共通処理の抽出も、実装が増えて重複が保守上の問題になった時点で判断する。

## 対応内容

### 1. 既存のPosts生成処理を回帰確認する

次を確認し、Issue #2で採用するMDX構成とずれがある場合だけ最小限修正する。

- `--slug` と位置引数のどちらでも指定できる。
- 引数の二重指定と余分な位置引数を拒否する。
- slugは小文字英数字と単一ハイフンの規則に従う。
- コンテンツ側または画像側の同名ディレクトリがあれば、何も上書きしない。
- 日本時間の日付が `YYYY-MM-DD` で入る。
- `post.yaml`、`ja.mdx`、`en.mdx`、画像用ディレクトリを生成する。
- 終了時に、次に編集するファイルと配置する画像を案内する。

### 2. Projects生成スクリプトを追加する

追加候補:

```text
scripts/create-project.mjs
```

コマンド:

```powershell
pnpm project:new -- --slug portfolio-site
```

生成物:

```text
src/content/projects/portfolio-site/
└─ project.yaml
```

初期YAMLは現在の `projectFileSchema` と同じキーだけを持つ。

```yaml
order: 1
url: ""

title:
  ja: ""
  en: ""

tags: []

description:
  ja: ""
  en: ""
```

空欄のscaffoldは、そのまま公開可能な完成データではない。生成直後に編集が必要であることを出力で明示する。

`order` は既存の `project.yaml` を読み、最大値の次を初期値にする。プロジェクトが0件なら1とする。既存YAMLを解析できない場合は、不正な状態を隠さず生成を中止する。将来、表示順を途中へ挿入したい場合は生成後に手動調整する。

### 3. `package.json` にコマンドを追加する

想定する追加:

```json
{
  "scripts": {
    "project:new": "node scripts/create-project.mjs"
  }
}
```

既存の `post:new` は名称を変更しない。添付ガイドや既存利用者との互換性を保つためである。

### 4. 失敗時の安全性を確認する

各スクリプトは書き込み前に、生成対象となるすべてのパスを確定して検証する。

- リポジトリ内の所定ディレクトリ以外へ書き込まない。
- `..`、絶対パス、無効なslugを受け付けない。
- 既存パスが1つでもあれば生成を開始しない。
- ファイル作成時は排他的作成を使い、競合時に上書きしない。
- エラー時は非0の終了コードを返す。

### 5. テストを追加する

実リポジトリの `src/content` を汚さないよう、一時ディレクトリを注入または指定できる小さな設計にする。少なくとも次を自動確認する。

- 有効なslugで期待する構成が生成される。
- 無効なslugで何も生成されない。
- 既存ディレクトリがある場合に上書きしない。
- Postsの日付が期待形式になる。
- Projectsの `order` が既存最大値の次になる。
- 生成されるYAMLにスキーマ外のキーがない。

## ドキュメント更新

実装後は、実際のコマンドと生成物に合わせて次を更新する。

- `README.md` または専用のコンテンツ入稿ガイド
- この計画書の現状欄
- コマンド名を参照するテストやCI

添付ガイドはリポジトリ外の参考資料なので、実装と同期させる正式なガイドが必要なら、内容を精査したうえで別途 `docs` 配下へ取り込む。

## 完了条件

- `post:new` と `project:new` の両方が利用できる。
- 各コマンドが正しいディレクトリと初期ファイルを生成する。
- 無効な入力と既存パスに対して安全に失敗する。
- 生成したscaffoldを編集すると、既存ローダーとスキーマで読み込める。
- 自動テストと `pnpm lint` が成功する。
