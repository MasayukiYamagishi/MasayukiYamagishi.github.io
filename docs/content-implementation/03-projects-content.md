# Projectsコンテンツの追加

## 目的

公開可能な個人開発プロジェクトを、Projectsセクションへ日本語・英語で追加する。単なる技術一覧ではなく、目的、担当範囲、技術的な特徴が短いカードから伝わる状態を目指す。

## 前提

- [コンテンツ作成用スクリプト](./02-content-scaffolding-scripts.md) の `project:new` が利用できる。
- 掲載先URLがHTTPSで公開されている。
- 業務案件の守秘情報、顧客情報、非公開URLを含めない。

具体的に掲載するプロジェクトはまだ確定していない。現在のポートフォリオサイト自身は候補になり得るが、この計画書では掲載決定とみなさない。

## プロジェクトごとに確定する情報

作業開始時に、次の表を1プロジェクトずつ埋める。

| 項目 | 確認内容 |
| --- | --- |
| slug | 公開後も変えない小文字英数字・ハイフン形式 |
| URL | リポジトリ、デモ、製品ページなど最も適切なHTTPS URL |
| 日本語タイトル | 50文字以内 |
| 英語タイトル | 日本語と同じ意味で50文字以内 |
| 日本語説明 | 目的、担当範囲、技術的特徴を200文字以内で説明 |
| 英語説明 | 日本語と同じ情報を200文字以内で説明 |
| タグ | 本当に説明価値のある主要技術だけを選ぶ |
| order | Projects全体での表示順 |
| 公開確認 | 秘密情報、顧客名、内部URL、誇張表現がないこと |

英語文は日本語の逐語訳に限定しないが、実績や担当範囲の意味を増減させない。

## 追加手順

### 1. 掲載対象と順番を決める

カード数を増やすこと自体を目的にしない。初回は、説明とリンクを検証できる少数の公開プロジェクトに絞る。

表示順は次の観点で決め、`order` の重複は避ける。

1. 現在目指す職種との関連性
2. UI品質、アクセシビリティ、パフォーマンスを示せるか
3. 実装の新しさと完成度

### 2. scaffoldを生成する

```powershell
pnpm project:new -- --slug <slug>
```

生成対象:

```text
src/content/projects/<slug>/project.yaml
```

生成後、空欄のままビルドしない。URL、日英テキスト、1件以上のタグを入力する。

### 3. タグを選ぶ

`src/components/ui/icons/TechnologyIcons.ts` に登録済みのIDを優先すると、ラベルと一緒にアイコンを表示できる。未登録IDもスキーマ上は使用できるが、カードではアイコンが表示されない。

新しいブランドアイコンを追加する場合は、ライセンスと利用条件を確認し、必要なら `THIRD_PARTY_NOTICES.md` と `licenses/` を更新する。アイコン追加はコンテンツ追加と分離できる場合、別コミットにする。

### 4. 自動検証を行う

```powershell
pnpm lint
pnpm exec vitest run
pnpm build
```

`projectFileSchema` により、正の整数の `order`、HTTPS URL、日英タイトル、1件以上の重複しないタグ、日英説明、未知キーの混入を検証する。

### 5. 目視確認を行う

日本語・英語のホームで次を確認する。

- `order` とslugによる並び順が意図どおりである。
- タイトルと説明がカード内で不自然に欠けない。
- 日英で事実関係と担当範囲が一致している。
- タグが多すぎず、ラベルとアイコンが適切である。
- カード全体をキーボードで操作でき、フォーカスが見える。
- 外部リンクが正しい公開先をHTTPSで開く。
- モバイル幅、ライトテーマ、ダークテーマで読みやすい。

## 変更単位

原則として1プロジェクトにつき1つの小さなコミットにする。レビュー時に、説明、URL、タグ、表示順をプロジェクト単位で確認しやすくするためである。

## 完了条件

- 合意したすべてのプロジェクトに `project.yaml` がある。
- 日英のタイトルと説明が揃い、意味が一致している。
- HTTPSのリンク先が有効で、公開可能な情報だけを含む。
- 表示順とタグが意図どおりである。
- 日本語・英語、モバイル、両テーマで表示確認が完了している。
- 品質確認コマンドがすべて成功する。
