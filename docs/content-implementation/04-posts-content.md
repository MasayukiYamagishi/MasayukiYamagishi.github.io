# Postsコンテンツの追加

## 目的

技術記事を、ホームのPosts一覧と日本語・英語の記事詳細ページへ追加する。タイトルや画像だけでなく、本文まで両言語で公開できる状態を「追加完了」とする。

## 前提

- [Issue #2](./01-issue-2-post-metadata-and-pages.md) が完了し、記事詳細ページが404にならない。
- [コンテンツ作成用スクリプト](./02-content-scaffolding-scripts.md) の `post:new` が利用できる。
- サムネイル、OG画像、本文画像の権利と公開可否を確認できる。

具体的に掲載する記事はまだ確定していない。添付ガイドの `published-my-zenn-article` はコマンド例であり、追加対象として確定したslugではない。

## 記事ごとに確定する情報

| 項目 | 確認内容 |
| --- | --- |
| slug | 公開後も変えない小文字英数字・ハイフン形式 |
| 記事の目的 | 読者が読み終えた後に得られるもの |
| 日本語タイトル・概要 | 内容を正確に表し、過度に誇張しない |
| 英語タイトル・概要 | 日本語と同じ対象・結論を示す |
| 公開日・更新日 | `YYYY-MM-DD`。更新日は公開日以降 |
| 日本語本文 | `ja.mdx` に記述 |
| 英語本文 | `en.mdx` に記述 |
| サムネイル | 16:9、1600×900以上、内容を表すalt付き |
| OG画像 | 1200:630、1200×630以上、内容を表すalt付き |
| 本文画像 | 必要な画像だけを使用し、本文側でaltを指定 |
| 出典・リンク | 引用元、参考資料、外部記事を正確に示す |

外部サービスに掲載済みの記事を紹介する場合は、全文の無断転載を避け、ポートフォリオ側で提供する独自の要約、補足、学びを明確にする。

## 追加手順

### 1. 記事の範囲を決める

初回は、MDX機能を広げなくても書ける記事を1件選ぶ。見出し、段落、リスト、リンク、コード、画像の基本機能を実コンテンツで検証できる題材が適している。

### 2. scaffoldを生成する

```powershell
pnpm post:new -- --slug <slug>
```

生成物:

```text
src/content/posts/<slug>/
├─ post.yaml
├─ ja.mdx
└─ en.mdx

assets/posts/<slug>/
└─ content/
   └─ .gitkeep
```

### 3. メタデータを入力する

`post.yaml` にタイトル、概要、公開日、必要なら更新日、サムネイルとOG画像のaltを記述する。

slug、生成後の画像パス、画像寸法はディレクトリ名とローダーから決まるため、YAMLに重複して書かない。未知のキーは厳密なスキーマ検証で失敗させる。

### 4. 日英の本文を作成する

`ja.mdx` と `en.mdx` の情報量と結論を揃える。記事タイトル、概要、日付は詳細ページがYAMLから表示するため、本文の先頭に重複させない。

初期の執筆ルール:

- 見出しは `h2` 相当から始め、階層を飛ばさない。
- リンクテキストだけで遷移先の意味が分かるようにする。
- コード例には可能なら言語を指定する。
- スクリーンショットだけで情報を伝えず、本文でも要点を説明する。
- 日英のどちらかだけを先行公開しない。

### 5. 原画像を配置して生成する

```text
assets/posts/<slug>/
├─ thumbnail.<supported-extension>
├─ og.<supported-extension>
└─ content/
   └─ <article-image>.<supported-extension>
```

```powershell
pnpm images:build
```

生成先の `public/images/posts/` は毎回再生成され、Git管理外である。生成物を手作業で編集しない。

同じベース名の入力画像を複数置かない。サムネイルとOG画像は必要寸法・アスペクト比を満たし、本文画像は変換後のファイル名をMDXから参照する。

### 6. 自動検証を行う

```powershell
pnpm images:build
pnpm lint
pnpm exec vitest run
pnpm build
```

次を失敗として扱う。

- YAMLの必須項目不足や未知キー
- 不正な日付やslug
- 日英どちらかの本文ファイル不足
- サムネイルまたはOG画像不足
- 同名入力画像の重複
- 必要寸法やアスペクト比を満たさない画像
- 記事詳細ルートの静的出力失敗

### 7. 目視確認を行う

日本語・英語の一覧と詳細ページで次を確認する。

- カードのタイトル、概要、日付、サムネイルが正しい。
- カードから同じ言語の記事へ遷移する。
- 本文の見出し、リスト、コード、画像、内部・外部リンクが正しい。
- 日英で事実関係、コード、結論が一致している。
- OG metadataのURL、画像、altが記事と一致している。
- モバイル幅で本文やコードが画面外へページ全体を押し出さない。
- ライト・ダークテーマ、キーボード操作、フォーカス表示に問題がない。

## 変更単位

原則として1記事につき1つのコミットにする。原稿の修正と記事基盤の修正が必要になった場合は、可能なら別コミットに分ける。

## 完了条件

- 合意した記事に、検証済みの `post.yaml`、`ja.mdx`、`en.mdx` がある。
- 必須画像が生成され、一覧と詳細ページで正しく表示される。
- 日英のカードと詳細ページが同じメタデータを使用する。
- カードのリンク先と静的出力が存在する。
- 日本語・英語、モバイル、両テーマで表示確認が完了している。
- 品質確認コマンドがすべて成功する。
