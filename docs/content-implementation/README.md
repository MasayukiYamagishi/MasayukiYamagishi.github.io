## 推奨する実施順

### 1. Issue #2を完了する（完了）

`/posts/<slug>` と `/en/posts/<slug>`、MDX本文の読み込み、静的ルート、ページ固有のメタデータを実装した。記事が0件でも静的exportを完了できる状態になっている。

### 2. 生成スクリプトを整える（完了）

既存の `post:new` をテスト可能な構成へ整理し、`project:new` を追加した。slug検証、上書き防止、日本時間の日付、Projectsの表示順計算を自動テストで確認している。

### 3. Projectsを追加する

画像や本文レンダリングを必要としないProjectsから追加し、YAML生成・検証・一覧表示の流れを確認する。

### 4. Postsを追加する

最後に、日英の本文と画像を含む記事を追加する。Issue #2と画像生成を含めたコンテンツ経路全体の受け入れ確認にもなる。

## 全体の完了条件

- 公開対象のProjectsとPostsが日本語・英語の両方で表示される。
- 記事カードから日英それぞれの詳細ページへ遷移できる。
- 新しいコンテンツは、記事ごとのimport追加なしでビルドへ反映される。
- `post:new` と `project:new` が既存ファイルを上書きせず、正しい初期ファイルを生成する。
- YAMLの不正、必須項目不足、不正なslugをビルドまたは生成時に検出できる。
- `pnpm test:scripts`、`pnpm lint`、`pnpm build` が成功する。
- モバイル幅、ライトテーマ、ダークテーマ、キーボード操作、日英表示を目視確認する。

## 今回まだ決めないこと

次の情報は、各コンテンツの作業開始時に本人が公開可否を判断して確定する。

- 掲載する具体的な記事とプロジェクト
- タイトル、説明、本文の日英原稿
- プロジェクトの外部URLと表示順
- 記事のサムネイル、OG画像、本文画像
- 業務上の守秘情報を含まないことの確認
